# Данные и безопасность

## Что можно передавать коллегам

Исходники этого репозитория, документацию и собранную страницу `INSTALL.html`. В шаблонах нет действующих ключей, адресов личных развертываний, данных конкретного сотрудника, корпоративного домена или его календаря. `owa.example.com` и остальные примеры в тестах — искусственные данные.

## Что нужно держать вне репозитория

- Ссылку подключения вида `/exec#ключ` и значение `BRIDGE_TOKEN`.
- Вывод `setup`, `showConnectionKey` и `rotateConnectionKey`, если он содержит ключ.
- Ссылки опубликованного рабочего календаря `.ics` и `.html`: длинная часть адреса может давать доступ к календарю без входа.
- Экспортированные ICS, названия, описания и ссылки реальных встреч, фотографии или скриншоты календаря.
- Cookie OWA, canary, заголовки авторизации, HAR, пароли, приватные ключи и файлы сертификатов с приватными ключами.
- Экспорт настроек Tampermonkey, параметры проекта Apps Script и личные вспомогательные функции с адресом собственного развертывания.

Адрес `/exec` без `#ключа` сам по себе не позволяет пройти проверку ключа нашего обработчика. Однако он идентифицирует личное развертывание, поэтому публичные примеры используют вымышленные адреса.

`.gitignore` помогает исключить такие файлы, но не удаляет сведения, уже записанные в Git или историю коммитов. Проверка `npm run check:sharing` — дополнительная проверка типичных утечек, а не гарантия отсутствия любых чувствительных сведений.

## Какие данные куда поступают

### Вход через Google (OAuth, с версии 1.3.0)

Публичный OAuth Client ID находится в `connect.js` и не является секретом. Client secret, JSON учётных данных и токены публиковать нельзя. Приложение запрашивает `calendar.app.created`, `openid` и `userinfo.email`: отдельный календарь приложения, идентификатор и адрес выбранного Google аккаунта. Полный доступ к личным календарям не запрашивается.

Страница подключения получает краткоживущий access token от Google Identity Services и передаёт его userscript через общее хранилище Tampermonkey. Запрос связан с открытой из OWA вкладкой случайным одноразовым nonce, действует 5 минут и проверяет адрес страницы, nonce и состояние ожидания. Между JavaScript страницы и изолированным контекстом userscript передаются строковые данные через DOM-события; командный атрибут удаляется сразу после обработки. Токен не остаётся в DOM и не записывается в URL. Связь через `window.opener` не используется.

Access token хранится локально в GM storage до истечения срока, отключения или удаления скрипта; при истечении повторный вход запрашивается действием пользователя. Пароли и refresh token приложение не получает. Адрес и идентификатор Google аккаунта нужны для отображения подключения и выбора календаря; сведения о календарях копий сохраняются локально для каждого аккаунта.

Встречи передаются напрямую с устройства в `www.googleapis.com`. В служебных метках копий — хеши профиля, источника и идентификатора встречи. Cookie и canary OWA в эти запросы не попадают. Сайт на GitHub Pages не принимает встречи и не содержит серверной базы данных. На странице подключения загружается официальная библиотека Google; GitHub и Google обрабатывают обычные сетевые запросы к своим сервисам.

Синхронизация меняет только помеченные копии своего профиля в созданном календаре «Работа · OWA». При переходе с Apps Script старый календарь сохраняется отдельно. На другом устройстве создаётся другой профиль и отдельный календарь. Неполный источник блокирует очистку.

«Отключить на этом устройстве» удаляет локальный токен, сохраняя календарь. Отозвать разрешение можно в [подключениях Google аккаунта](https://myaccount.google.com/connections), удалить копии — удалением календаря в Google. Не преобразуйте управляемые копии в серии: конфликт останавливает синхронизацию.

[Публичное описание обработки данных](https://mainiken.github.io/owa-calendar-bridge/privacy.html).

### Локальный кеш встреч

С версии 1.4.0 хранилище Tampermonkey содержит также подготовленные названия, время, описания, место и ссылки встреч из последнего прочитанного периода. Вместо исходных Exchange ID и версий сохраняются их хеши. Это позволяет не перечитывать неизменённые описания. Кеш остаётся на устройстве и не передаётся сайту подключения. Экспорт хранилища Tampermonkey поэтому может содержать рабочие данные и токены: не публикуйте его.

Меню «Полная проверка при следующей синхронизации» удаляет локальный кеш чтения и подтверждения Apps Script для текущего подключения, сохраняя календарь и вход. Удаление самого userscript удаляет его хранилище согласно настройкам расширения. Для Apps Script подтверждения передачи действуют сутки, после чего события повторно сверяются обработчиком.

### Дополнительный способ через собственный Apps Script

OWA получает запросы чтения в текущей пользовательской сессии. Пользовательский пароль и сертификат в скрипте не сохраняются. Cookie и canary используются только при обращении к тому же OWA и не включаются в запросы Google.

После нажатия «Синхронизировать» обработчик Google получает названия, время, место, описания и ссылки выбранных встреч, диапазон, имя сервера OWA, идентификатор профиля и хешированные идентификаторы событий. Обработчик записывает копии в собственный календарь пользователя. Само содержимое встреч при этом передаётся в Google и сохраняется в этом аккаунте. Хеширование идентификаторов не обезличивает названия и описания.

Не передавайте рабочие данные в личный Google аккаунт, если это запрещено правилами вашей организации. Публикация программного кода и разрешение на выгрузку рабочих данных — разные вопросы.

Авторизация Apps Script запрашивает доступ к календарям Google аккаунта. Это разрешение шире, чем один календарь «Работа»; реализация выбирает только календарь, созданный обработчиком, и меняет только помеченные копии своего профиля.

## Apps Script: почему веб-приложение доступно «Всем»

Tampermonkey вызывает обработчик без Google cookie. Развертывание выполняется от имени владельца, а операции проверяют случайный 64-символьный ключ из тела POST-запроса. Ключ не передаётся в query string. Без него `doGet` возвращает только название сервиса и версию, а операции записи отклоняются.

Обладатель действующего ключа может обращаться к обработчику и менять управляемые им копии событий. Поэтому каждому пользователю нужен собственный проект и ключ. Не делайте общий обработчик для коллег и не публикуйте ссылку подключения.

## Если ключ оказался раскрыт

1. В собственном редакторе Apps Script выберите и выполните `rotateConnectionKey`.
2. Скопируйте новый ключ из журнала. Допишите его к текущему адресу `/exec` после `#` и обновите настройки Tampermonkey.
3. Предыдущий ключ перестанет проходить проверку последующих запросов. Календарь и сохранённые копии сохраняются.

Если старая опубликованная версия обработчика ещё не содержит эту функцию, замените код актуальным, сохраните и выполните её в редакторе. Свойства проекта общие для развертываний, поэтому замена ключа доступна действующему обработчику.

Для раскрытой ссылки опубликованного OWA-календаря отмените публикацию и получите новые ссылки в OWA либо обратитесь к администратору. Изменения `.gitignore` или удаление ссылки из последнего коммита не отзывают доступ по уже раскрытому адресу.

## Ограничения

Это личные копии календаря, которые обновляются только вручную. Ошибка или изменение OWA может задержать обновление встречи. Полнота списка требуется для удаления; неполное чтение не запускает очистку. При сбое записи часть копий может обновиться раньше остальных.

В сообщении о проблеме указывайте версию, шаги и текст ошибки с панели. Удаляйте реальные данные встреч и ключи из любых приложений к сообщению.
