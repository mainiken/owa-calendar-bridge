# OWA Calendar Bridge

**Кнопка для ручной синхронизации рабочего календаря из открытого Outlook Web App в Google Календарь.**

Днём вы работаете с включённым корпоративным подключением и открытым OWA. Входите через Google и нажимаете **«Синхронизировать»** — встречи появляются в отдельном Google-календаре **«Работа · OWA»**: с названиями, временем, описаниями, местом и ссылками на звонки. Следующий запуск обновляет копии.

[![Проверки](https://github.com/mainiken/owa-calendar-bridge/actions/workflows/checks.yml/badge.svg)](https://github.com/mainiken/owa-calendar-bridge/actions/workflows/checks.yml)
[![MIT](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

**[Открыть страницу установки](https://mainiken.github.io/owa-calendar-bridge/)** · [Установить userscript по ссылке](https://raw.githubusercontent.com/mainiken/owa-calendar-bridge/main/owa-google-sync.user.js) · [Данные и безопасность](SECURITY.md)

Скачивать архив не требуется: страница установки работает прямо в браузере. Для получения всего проекта используйте Git:

```sh
git clone https://github.com/mainiken/owa-calendar-bridge.git
cd owa-calendar-bridge
```

Или с GitHub CLI: `gh repo clone mainiken/owa-calendar-bridge`. После клонирования можно открыть `INSTALL.html` локально; устанавливать Node.js для этого не нужно. **Code → Download ZIP** и [архивы релизов](https://github.com/mainiken/owa-calendar-bridge/releases) остаются дополнительными вариантами.

**С версии 1.3.0 есть вход через Google:** отдельный Apps Script и ключ для каждого пользователя не требуются. OAuth-приложение использует общий публичный Client ID. Для этапа тестирования владелец добавляет адреса участников в **Google Auth Platform → Audience → Test users**. [Настройка приложения владельцем](docs/GOOGLE-OAUTH.md).

## Перед установкой

Нужны компьютер, браузер с Tampermonkey, рабочий доступ к OWA и Google аккаунт, в котором вы хотите видеть копии встреч. Программирование, Node.js, терминал и консоль браузера для установки не нужны.

Каждый пользователь входит в собственный Google аккаунт. Коллегам передаётся ссылка на страницу установки или репозиторий. Прежний способ через личный Apps Script остаётся доступен в настройках.

**На MacBook:** используйте Chrome или Firefox с Tampermonkey. В сочетаниях ниже вместо Ctrl используйте **⌘**: **⌘A**, **⌘V**, **⌘S**; обновление страницы — **⌘R**. Реальный вход и синхронизация на macOS пока ожидают проверки.

Скрипт переносит содержание выбранных встреч в Google. Используйте его для данных, перенос которых разрешён организацией. Разрешения описаны в [SECURITY.md](SECURITY.md).

## Установка по шагам

### 1. Откройте страницу установки

1. Откройте **[страницу установки](https://mainiken.github.io/owa-calendar-bridge/)**. В браузере появится страница «Рабочие встречи рядом с личными».
2. Оставьте её открытой: на ней есть поле адреса OWA и кнопки копирования кода.

Дальше под «страницей установки» / `INSTALL.html` понимается как эта веб-страница, так и локальный файл из клонированного проекта. Они содержат одинаковые инструкции и скрипты.

### 2. Укажите адрес своей почты OWA

1. Включите корпоративный VPN или другое подключение, которое обычно нужно для работы.
2. Откройте рабочую почту обычным способом. Если требуется сертификат, выберите свой сертификат и войдите как всегда.
3. Скопируйте адрес из адресной строки. Обычно он выглядит так:

   ```text
   https://owa.example.com/owa/
   ```

4. В открытом **`INSTALL.html`** вставьте его в поле **«Адрес вашей почты OWA»**. Страница уберёт параметры отображения и хвост вроде `#path=/calendar`.

`owa.example.com` — **пример**. Нужен настоящий адрес вашей организации. Возьмите рабочую закладку или уточните адрес в ИТ-поддержке.

Нужна обычная авторизованная почта с путём `/owa/`. Ссылки опубликованного календаря `calendar.html` и `calendar.ics` не подходят. Отдельный интерфейс `outlook.office.com` в Microsoft 365 не поддерживается.

Страница установки подставит сервер в правила запуска скрипта. Адрес обрабатывается на вашем компьютере, без отправки внешнему сервису. Пароль, сертификат и cookie вводить не нужно.

### 3. Установите Tampermonkey

Tampermonkey — расширение браузера для запуска пользовательских скриптов на выбранных сайтах.

1. Откройте **[официальный сайт Tampermonkey](https://www.tampermonkey.net/)** в том браузере, где пользуетесь OWA.
2. Выберите свой браузер: **Chrome**, **Microsoft Edge** или **Firefox**.
3. У обычной версии **Tampermonkey** нажмите **Get from Store / «Установить»**.
4. В открывшемся магазине нажмите **«Установить» / «Добавить»** и подтвердите установку расширения.
5. В Chrome/Edge нажмите значок **пазла «Расширения»** справа от адресной строки и закрепите Tampermonkey.

В Firefox после установки переходите к шагу 5. Для Chrome/Edge сначала разрешите запуск скриптов.

### 4. Разрешите запуск скриптов в Chrome/Edge

**Chrome:**

1. Введите **`chrome://extensions/`** в адресной строке новой вкладки и нажмите Enter.
2. Найдите **Tampermonkey → «Сведения» / Details**.
3. Включите **«Разрешить пользовательские скрипты» / Allow User Scripts**, если такой переключатель есть.
4. Если его нет, вернитесь к списку расширений и включите **«Режим разработчика» / Developer mode**.
5. Проверьте **«Доступ к сайтам»**: расширению должен быть разрешён доступ к вашему OWA.

**Microsoft Edge:**

1. Откройте **`edge://extensions/`**.
2. Проверьте, что Tampermonkey включён и ему разрешён доступ к OWA.
3. Включите доступный переключатель запуска пользовательских скриптов; если его нет — **«Режим разработчика»** в управлении расширениями.

Варианты разрешения описаны в [официальной инструкции Tampermonkey Q209](https://www.tampermonkey.net/faq.php?q=Q209). Если рабочая политика браузера блокирует установку или переключатель, понадобится разрешение администратора.

### 5. Добавьте кнопку в OWA

1. Вернитесь в **`INSTALL.html`** и проверьте адрес своего OWA.
2. Нажмите **«Скопировать userscript»**.
3. В меню Tampermonkey выберите **«Создать новый скрипт» / Create a new script**. В панели управления также можно нажать вкладку **«+»**.
4. Щёлкните внутри редактора кода → **Ctrl+A → Ctrl+V**, чтобы полностью заменить шаблон скопированным кодом.
5. Нажмите **Ctrl+S** или **Файл → Сохранить**.
6. В Tampermonkey должен появиться включённый скрипт **«OWA → Google: мой календарь»**.
7. Вернитесь в обычную авторизованную вкладку OWA и обновите её клавишей **F5**.

**Результат:** справа снизу появится панель **«Работа → Google Календарь»** с кнопками «Синхронизировать», «Просмотр» и «Скачать ICS».

**Установка непосредственно по ссылке:** после установки и настройки Tampermonkey откройте [исходный `.user.js`](https://raw.githubusercontent.com/mainiken/owa-calendar-bridge/main/owa-google-sync.user.js). Если расширение перехватит ссылку, появится его окно с кнопкой **«Установить»**. Этот общий вариант запускается на HTTPS-сайтах с путём `/owa/`. Чтобы ограничить его своим сервером, измените `@match` и `@exclude` по [примеру ниже](#где-настраивается-адрес-owa) либо используйте подготовку кода на странице установки. Если браузер показывает только текст, используйте копирование кода из шагов выше.

При повторной установке обновляйте существующий скрипт. Две включённые копии могут показывать две панели и использовать разные профили.

### 6. Проверьте чтение встреч

1. На панели в OWA нажмите **«Просмотр»**.
2. Дождитесь завершения чтения.
3. Проверьте, что появились **названия ваших встреч** и количество прочитанных событий.

Здесь встречи в Google не передаются. Если чтение не работает, сначала решите проблему по разделу [«Если что-то не работает»](#если-что-то-не-работает).

### 7. Войдите через Google

1. На панели в OWA нажмите **⚙** и выберите **«Войти через Google»** в способе подключения.
2. Нажмите синюю кнопку **«Войти через Google»**. Откроется новая вкладка `mainiken.github.io/owa-calendar-bridge/connect.html`.
3. Разрешите Tampermonkey доступ к этой странице, если потребуется.
4. На новой странице нажмите **«Войти через Google»**, выберите аккаунт и разрешите создание календарей приложения и доступ к адресу аккаунта.
5. Дождитесь сообщения о передаче доступа, вернитесь в OWA: в настройках появится адрес аккаунта.
6. Выберите 30/60/90 дней и нажмите **«Сохранить»**.

При `access_denied` владелец приложения должен добавить Google адрес участника в **Audience → Test users**. При `origin_mismatch` проверьте Authorized JavaScript origins: **`https://mainiken.github.io`**, без пути проекта. Если userscript не отвечает на странице входа, проверьте версию 1.3.0 и доступ Tampermonkey к `mainiken.github.io`.

Вход ограничен временем жизни access token. При истечении повторите подключение кнопкой; календарь и идентификаторы копий сохраняются. Refresh token и пароль Google не сохраняются.

### 8. Запустите синхронизацию

1. В OWA нажмите **«Синхронизировать»**.
2. Разрешите userscript обращаться к **`www.googleapis.com`**, если Tampermonkey спросит.
3. Дождитесь **«Готово»** со счётчиками событий.
4. Откройте [Google Календарь](https://calendar.google.com/) в подключённом аккаунте, включите календарь **«Работа · OWA»** и проверьте встречу.

При переходе с Apps Script OAuth создаёт отдельный календарь. Старый **«Работа»** сохраняется: скройте его, чтобы оба набора не отображались одновременно. Удаление userscript или локального входа не удаляет копии в Google. На другом устройстве создаётся отдельный профиль и календарь копий.

## Дополнительный способ: собственный Apps Script

Если уже используется этот способ, обновление сохранит его выбор и ссылку. Для новой установки выберите **«Мой Google Apps Script»** в настройках. Дальнейшие шаги относятся только к этому варианту.

### 1. Создайте собственный обработчик Google

1. Откройте **[Google Apps Script](https://script.google.com/home/start)**.
2. По аватару справа сверху проверьте аккаунт: это должен быть Google аккаунт, в календаре которого нужны встречи.
3. Нажмите **«Новый проект» / New project**.
4. Нажмите название «Проект без названия» и назовите его, например **OWA Calendar Bridge**.
5. В `INSTALL.html` нажмите **«Скопировать обработчик Google»**.
6. В редакторе Apps Script откройте **`Код.gs` / `Code.gs`**.
7. Щёлкните внутри редактора → **Ctrl+A → Ctrl+V**, чтобы полностью заменить шаблон.
8. Сохраните проект кнопкой сохранения или **Ctrl+S**.

В файле [GoogleCalendarBridge.gs](GoogleCalendarBridge.gs) лежит тот же обработчик. Каждый коллега создаёт свой проект в своём аккаунте.

### 2. Разверните обработчик

1. Справа сверху: **«Начать развертывание» / Deploy → «Новое развертывание» / New deployment**.
2. Возле выбора типа нажмите **шестерёнку → «Веб-приложение» / Web app**.
3. В описании можно написать **Личный календарь OWA**.
4. Выставьте параметры:

   | Поле | Значение |
   | --- | --- |
   | Выполнять от имени / Execute as | **Я / Me** |
   | У кого есть доступ / Who has access | **Все / Anyone**, включая пользователей без входа в Google |

5. Нажмите **«Развернуть» / Deploy**.
6. Если Google запрашивает авторизацию: **«Разрешить доступ» / Authorize access**, выберите свой аккаунт и подтвердите доступ к календарям для созданного вами проекта. Разрешение шире одного календаря; сам код работает с отдельным календарём «Работа».
7. Если показано предупреждение о непроверенном приложении, проверьте, что это ваш созданный проект с вашим кодом. Для собственного проекта может быть доступен переход через **«Дополнительные настройки»** к авторизации. При блокировке политикой организации обратитесь к администратору.
8. Скопируйте **URL веб-приложения**, заканчивающийся на **`/exec`**, и сохраните его у себя.

Пример формы адреса:

```text
https://script.google.com/macros/s/DEPLOYMENT_ID/exec
```

Для подключения к этому адресу нужно добавить ключ на следующем шаге. Обработчик доступен без входа в Google, а запись дополнительно защищена ключом. [Документация Google о развертывании](https://developers.google.com/apps-script/guides/web).

### 3. Получите ссылку с ключом

1. Вернитесь в редактор Apps Script.
2. В верхней панели рядом с **«Выполнить»** и **«Отладка»** откройте список функций.
3. Выберите именно **`setup`** и нажмите **«Выполнить» / Run**.
4. При дополнительном запросе авторизации завершите её для своего проекта.
5. Откройте **«Журнал выполнения» / Execution log** и дождитесь завершения.
6. Обработчик создаст отдельный календарь **«Работа»** и покажет данные подключения.

**Если появилась готовая ссылка:** скопируйте её целиком, включая `#` и ключ после него.

```text
https://script.google.com/macros/s/DEPLOYMENT_ID/exec#ВАШ_КЛЮЧ
```

**Если показан отдельно ключ:** к адресу `/exec` из развертывания допишите знак **`#`**, затем ключ из журнала, без пробелов. Получится строка того же вида.

Реальный ключ — 64 символа. `DEPLOYMENT_ID` и `ВАШ_КЛЮЧ` выше являются пояснениями; используйте свои значения.

Храните ссылку подключения у себя. Не публикуйте её и журнал с ключом. Снова показать существующий ключ можно функцией **`showConnectionKey`**: выберите её в верхнем списке и нажмите «Выполнить».

### 4. Подключите Google в OWA

1. Во вкладке OWA на панели **«Работа → Google Календарь»** нажмите **⚙**.
2. В **«Ссылка подключения»** вставьте всю строку **`/exec#ключ`**.
3. Выберите период: **30**, **60** или **90 дней вперёд**. Также обновляются последние 7 дней.
4. Нажмите **«Сохранить»**, затем **«Синхронизировать»**.
5. Если Tampermonkey спрашивает разрешение на `script.google.com` или `script.googleusercontent.com`, разрешите обращение скрипта к этим адресам Google.
6. Дождитесь **«Готово»** со счётчиками событий.

### 5. Проверьте результат в Google

1. Откройте **[Google Календарь](https://calendar.google.com/)** в том же аккаунте, где создали обработчик.
2. Обновите страницу и найдите слева календарь **«Работа»**.
3. Включите его отображение и откройте дату одной из рабочих встреч.
4. Проверьте название, время, описание и ссылку на звонок.

Если календарь с названием «Работа» уже существовал, обработчик создаёт свой и сохраняет его идентификатор в свойствах проекта.

## Как пользоваться каждый день

1. В рабочее время включите нужное корпоративное подключение и войдите в OWA.
2. Нажмите **«Синхронизировать»** и дождитесь **«Готово»**.

В Google видна последняя полученная версия расписания. Между нажатиями изменения не поступают. Если встречу перенесли или отменили, нажмите кнопку снова, когда OWA доступен.

| Кнопка | Действие |
| --- | --- |
| Синхронизировать | Чтение OWA и обновление копий в Google |
| Просмотр | Названия встреч без передачи их в Google |
| Скачать ICS | Разовый экспорт с полными данными без подключения Google |
| ⚙ | Ссылка подключения и период |
| − / + | Свернуть или развернуть панель |

## Если что-то не работает

| Что произошло | Что проверить |
| --- | --- |
| Google: `access_denied` | Владелец добавил ваш Google адрес в Audience → Test users; доступ разрешён при входе. |
| Google: `origin_mismatch` | В настройках OAuth-клиента origin `https://mainiken.github.io`, без пути и завершающего `/`. |
| Userscript не отвечает на странице входа | Версия 1.3.0, один экземпляр скрипта, разрешение Tampermonkey на mainiken.github.io. Начните вход из OWA заново. |
| Вход Google истёк | Настройки OWA → «Войти через Google» повторно. Календарь копий сохраняется. |
| Google API: HTTP 403 | Calendar API включён, предоставлены разрешения calendar.app.created и адрес аккаунта. |
| Нет панели | Tampermonkey включён, разрешён запуск userscript и доступ к OWA, код сохранён, вкладка обновлена. Домен в `@match` соответствует открытой почте. |
| Открыт публичный календарь | Вернитесь в обычную авторизованную почту `/owa/`. Опубликованные `calendar.html` и `.ics` не используются. |
| «Не вижу активного входа OWA» или «OWA отклонил запрос» | Проверьте корпоративное подключение и повторно войдите в OWA обычным способом. |
| Непонятный формат ответа OWA | Версия сервера может отличаться. Передайте сопровождающему текст ошибки с панели без cookie, ключей и данных встреч. |
| «Нужна ссылка … /exec#ключ» | Вставьте адрес развертывания вместе с `#` и своим 64-символьным ключом. |
| `setup` показывает только ключ | Допишите ключ через `#` к адресу `/exec` из развертывания. Повторно разворачивать для этого не нужно. |
| Выполняется другая функция | В списке функций сверху явно выберите нужную, затем нажмите «Выполнить». |
| Google требует входа | **Управление развертываниями → своё веб-приложение → карандаш**: выполнять от имени **Я**, доступ **Все**, включая пользователей без входа. Сохраните существующее развертывание. |
| Неверный ключ | Выполните `showConnectionKey` в своём проекте и обновите строку `/exec#ключ` в OWA. |
| В опубликованной версии нет `doPost` | Обновите существующее развертывание до новой версии с кодом обработчика. Сохранение кода само по себе опубликованную версию не обновляет. |
| В Google пусто после «Готово» | Проверьте аккаунт Google, отображение календаря «Работа» и выбранную дату. |
| OWA не подтвердил полный список | Прочитанные события обновлены, очистка пропущена. Повторите запуск позже. |

**Проверка обработчика:** откройте свой адрес `/exec` **без `#ключа`** в окне инкогнито. Должен появиться JSON с `OWA Calendar Bridge` без запроса входа. Этот ответ не содержит ключа или встреч.

## Что переносится и какие есть ограничения

- Название, время, место, текст описания и ссылки на звонки.
- Последние 7 дней и выбранный период вперёд; до 1000 событий за запуск.
- Повторяющиеся встречи разворачиваются в отдельные события в пределах периода.
- Участники не добавляются; приглашения и ответы организаторам не отправляются.
- Описания ограничены 16 000 символами до HTML-экранирования; вложения и изображения не копируются.
- Часовой пояс календаря и событий на весь день — **Europe/Moscow**.
- Повторный импорт ICS не заменяет синхронизацию и может создавать дубли.
- Не превращайте управляемые копии вручную в серии и не используйте их для ответов организатору.

Исчезнувшие события удаляются только после успешного чтения полного списка OWA и успешной передачи всех копий. При ошибке чтения передачи нет. При ошибке Google часть событий может обновиться, но очистка не запускается; следующий запуск повторяет синхронизацию.

Ручная синхронизация подтверждена пользователем на одном сервере OWA. Совместимость со всеми версиями Exchange не проверена: используется внутренний JSON-интерфейс OWA. Microsoft 365 с другим интерфейсом и нестандартные пути могут потребовать адаптации.

## Где настраивается адрес OWA

Используйте поле **«Адрес вашей почты OWA»** на [странице установки](https://mainiken.github.io/owa-calendar-bridge/): она подготовит скрипт для указанного сервера.

При ручной установке из исходника можно изменить две строки в начале `owa-google-sync.user.js`:

```js
// @match        https://owa.example.com/owa/*
// @exclude      https://owa.example.com/owa/calendar/*
```

Замените пример своим сервером. Исходный шаблон `https://*/owa/*` сопоставляется со всеми такими HTTPS-доменами. Внутри кода адрес менять не нужно: запросы идут на сервер текущей вкладки. В обработчике Google корпоративный домен не указывается.

## Обновление и смена ключа

Для Tampermonkey замените код существующего скрипта. Если ограничивали сервер, подготовьте код через `INSTALL.html` с тем же адресом OWA.

Для Google замените код и обновите существующее развертывание: **Управление развертываниями → карандаш → Версия: Новая версия → Развернуть**. Календарь и ключ хранятся в свойствах проекта; ссылка существующего развертывания сохраняется.

Если ключ раскрыт, выполните **`rotateConnectionKey`** и обновите ссылку подключения в OWA. Календарь сохраняется. Подробности — [SECURITY.md](SECURITY.md).

## Для разработчиков

Требуется Node.js 22.19+.

```sh
npm ci
npm test
```

Тесты используют искусственные ответы OWA, имитацию Google Calendar и DOM. Реальные запросы к корпоративной почте и Google не выполняются. `npm run build` собирает автономный `INSTALL.html`; `npm run check:sharing` проверяет публикуемые файлы и вложенный код страницы на признаки личных подключений и секретов.

Состав файлов: [docs/SHARING.md](docs/SHARING.md). Изменения: [CHANGELOG.md](CHANGELOG.md).
