# Вход через Google: настройка приложения один раз для всех

Это инструкция **владельцу приложения**, не каждому коллеге. С версии 1.3.0 userscript поддерживает Google Identity Services и прямую запись в Calendar API. Публичный Client ID настроен в `connect.js`. С версии 1.5.0 client secret используется только в закрытом окружении серверной службы для автоматического продления доступа.

Сценарий для коллеги: установить Tampermonkey и userscript → нажать «Войти через Google» в настройках OWA → подтвердить вход на странице подключения → выбрать аккаунт и разрешить доступ → синхронизировать из открытого OWA. Apps Script и собственный ключ подключения не требуются. Реальная авторизация Google и совместимость с macOS ещё должны быть проверены на пользовательском устройстве; локальные проверки используют имитацию API.

Google-авторизация даёт доступ к Google Календарю. Читать корпоративный календарь продолжит userscript в авторизованной вкладке OWA, с доступным VPN и сертификатом.

## 1. Создайте проект в Google Cloud

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) в своём Google аккаунте — владельце приложения.
2. В верхней панели откройте список проектов → **«Создать проект» / New project**.
3. Назовите проект **OWA Calendar Bridge** и нажмите **«Создать» / Create**.
4. Дождитесь создания и выберите этот проект в верхней панели.

Для этой настройки не создавайте платные виртуальные машины и не вставляйте платёжные реквизиты: здесь нужны Calendar API и OAuth.

## 2. Включите Google Calendar API

1. Откройте **APIs & Services → Library / API и сервисы → Библиотека**.
2. Найдите **Google Calendar API** и нажмите **Enable / Включить**.
3. [Прямая страница Calendar API](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com) — перед включением проверьте выбранный проект.

## 3. Настройте Google Auth Platform

1. Откройте **Google Auth Platform** в меню Cloud Console. В некоторых вариантах интерфейса вход находится через **APIs & Services → OAuth consent screen**.
2. Если видите **Get started / Начать**, нажмите её.
3. **App information / Информация о приложении:** имя **OWA Calendar Bridge**; выберите контактную почту поддержки.
4. **Audience / Аудитория:** **External / Внешняя**, чтобы разрешить личные Google аккаунты коллег.
5. Введите контактную почту владельца, подтвердите условия и завершите создание.

Имя приложения и адрес поддержки могут отображаться пользователям на экране согласия. Не указывайте чужие контакты.

## 4. Добавьте разрешение календаря

1. Откройте **Data Access / Доступ к данным → Add or remove scopes / Добавить или удалить разрешения**.
2. Найдите и добавьте только:

   ```text
   https://www.googleapis.com/auth/calendar.app.created
   ```

3. Если поиск не показывает его, используйте поле ручного добавления разрешений.
4. Сохраните изменения.

Также добавьте `openid` и `https://www.googleapis.com/auth/userinfo.email`: они нужны для определения аккаунта и отображения его адреса в настройках. Код запрашивает именно эти три разрешения.

Этот scope позволяет создавать дополнительные календари и работать с событиями календарей, созданных приложением. Он подходит для отдельного календаря копий «Работа». Полный `calendar` и доступ ко всем личным событиям для этого сценария не нужны. [Официальное описание разрешений Calendar API](https://developers.google.com/workspace/calendar/api/auth).

Не обещайте пользователям отсутствие проверки Google: необходимость проверки зависит от разрешений и настроек приложения. Классификация и требования будут показаны в Google Auth Platform. [Требования проверки разрешений](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification).

## 5. Добавьте себя для первого теста

1. Откройте **Audience / Аудитория**.
2. На этапе **Testing / Тестирование** добавьте свой Google адрес в **Test users / Тестовые пользователи**.
3. Для закрытого теста позже добавьте адреса участвующих коллег.

Публичность репозитория GitHub не делает OAuth-приложение доступным всем. Для общего запуска отдельно настраиваются публикация приложения и, если потребуется, проверка Google. Сначала проверим вход на тестовом аккаунте.

## 6. Создайте OAuth Client ID

1. Откройте **Clients / Клиенты → Create client / Создать клиента**.
2. Тип приложения — **Web application / Веб-приложение**.
3. Имя — например **OWA Calendar Bridge Web**.
4. В **Authorized JavaScript origins / Разрешённые источники JavaScript** добавьте:

   ```text
   https://mainiken.github.io
   ```

5. Указывайте именно origin: **без** `/owa-calendar-bridge/`, пути страницы и завершающего `/`.
6. **Authorized redirect URIs** для браузерного popup-потока Google Identity Services заполнять не требуется.
7. Нажмите **Create / Создать**.
8. Скопируйте **Client ID / Идентификатор клиента**. Он обычно заканчивается на:

   ```text
   .apps.googleusercontent.com
   ```

Если интерфейс предлагает **Client secret**, его не копируйте в переписку, userscript или репозиторий. В браузере используется только Client ID. Для серверной службы владелец сохраняет JSON учётных данных локально и настраивает client secret в закрытом окружении по [инструкции службы](AUTH-SERVICE.md). Коллегам этот файл не нужен.

Origin относится к опубликованной странице этого проекта. Если размещаете собственную копию, укажите origin своего сайта и используйте собственный OAuth-клиент. [Настройка OAuth для браузерных приложений](https://developers.google.com/identity/protocols/oauth2/javascript-implicit-flow).

## 7. Что передать для подключения

Для браузерной страницы нужен **Client ID**, заканчивающийся на `.apps.googleusercontent.com`. Это публичная настройка приложения. Client secret настраивается только на сервере владельца; пользователям пароль, токены и секрет приложения передавать не нужно.

Client ID подключается в `connect.js`. Для текущего проекта он уже указан. Перед первым тестом проверьте **Audience → Test users**, разрешения из шага 4 и origin из шага 6. Откройте вход из обновлённого userscript в OWA. Прежний Apps Script остаётся дополнительным способом подключения.

Для заполнения Branding доступны страницы:

- Homepage: `https://mainiken.github.io/owa-calendar-bridge/`
- Privacy policy: `https://mainiken.github.io/owa-calendar-bridge/privacy.html`

Публикация страниц сама по себе не означает прохождение проверки Google. Для открытого запуска следуйте требованиям, показанным в Verification centre.

## Как работает авторизация

С версии 1.5.0 используется GIS authorization code flow с серверным обменом кода и зашифрованным хранением refresh token. Вход выполняется один раз, при обычном истечении access token синхронизация продлевает его автоматически. Встречи передаются напрямую из браузера в Calendar API. [Развёртывание службы, настройка Production и ограничения Google](AUTH-SERVICE.md).
