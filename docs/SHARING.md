# Передача коллегам и подготовка к публикации

## Пакет для установки

Основной способ — [страница установки](https://mainiken.github.io/owa-calendar-bridge/): её можно открыть без скачивания. Весь проект доступен через `git clone https://github.com/mainiken/owa-calendar-bridge.git` или `gh repo clone mainiken/owa-calendar-bridge`. Node.js требуется только для разработки и пересборки страницы, не для использования.

Архив релиза — дополнительный способ установки без сети. В нём есть `INSTALL.html`, оба исходных скрипта, `README.md`, `SECURITY.md`, `LICENSE`, `CHANGELOG.md` и эта инструкция. Получатель открывает `INSTALL.html` и проходит установку в собственных аккаунтах.

Для сообщения коллегам можно использовать такой текст:

> Сделал кнопку для ручной синхронизации своего календаря из открытого OWA в отдельный Google Календарь. Переносятся названия, время, описания и ссылки на звонки. Страница установки: https://mainiken.github.io/owa-calendar-bridge/. Установите userscript и войдите через Google; для теста ваш Google адрес должен быть добавлен владельцем приложения в Test users. Используйте для данных, перенос которых разрешён организацией.

## Чистый репозиторий

Репозиторий создан из явного списка исходных файлов. В него не переносились временные ответы сайтов, загруженные скрипты OWA, диагностические файлы, пользовательская вспомогательная функция подключения или скриншоты.

Корпоративный домен заменён получением имени текущего сервера OWA. Тесты используют `example.com`. Адрес личного развертывания отсутствует. Существующая рабочая установка пользователя хранится отдельно от этого репозитория.

Перед первым публичным размещением:

```sh
npm ci
npm test
git status --short
git ls-files
```

Просмотрите именно список отслеживаемых файлов и историю. `.gitignore` не защищает секреты, вписанные непосредственно в разрешённый исходник или текст документации.

Публичный репозиторий: https://github.com/mainiken/owa-calendar-bridge. В публичную историю включены только проверенные исходники и документация. Начальный коммит использует нейтральную подпись `OWA Calendar Bridge contributors <contributors@example.invalid>`.

## Ограничение разрешений Tampermonkey

Исходный шаблон сопоставляется с HTTPS-адресами `https://*/owa/*`, а публичные страницы `https://*/owa/calendar/*` исключены. Страница `INSTALL.html` принимает адрес OWA и подготавливает скрипт с `@match` и `@exclude` только для этого сервера. Обработка адреса идёт локально. Адрес домена — публичная конфигурация, не пароль, но он может показывать, для какой организации сделан вариант инструмента.

При OAuth источник входит в хеш владельца копий; разные серверы используют разные метки событий. При Apps Script имя сервера передаётся собственному обработчику и закрепляется за профилем при первом изменении календаря. Перенос одного профиля Apps Script на другой сервер отклоняется.

Публичный Client ID можно передавать вместе с кодом. JSON с Client secret, токены и файлы из локальной папки private/ не публикуются. На странице подключения userscript дополнительно работает на одном точном адресе `https://mainiken.github.io/owa-calendar-bridge/connect.html` для передачи разрешения между вкладками.
