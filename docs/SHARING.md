# Передача коллегам и подготовка к публикации

## Пакет для установки

В архиве для коллег есть `INSTALL.html`, оба исходных скрипта, `README.md`, `SECURITY.md`, `LICENSE`, `CHANGELOG.md` и эта инструкция. Получатель открывает `INSTALL.html` и проходит установку в собственных аккаунтах. Node.js требуется только для разработки и пересборки страницы, не для использования.

Для сообщения коллегам можно использовать такой текст:

> Сделал кнопку для ручной синхронизации своего календаря из открытого OWA в отдельный Google Календарь. Переносятся названия, время, описания и ссылки на звонки. Установка описана в INSTALL.html. Каждый создаёт собственный обработчик Google и ключ; личные ссылки подключения друг другу не передаём. Используйте для данных, перенос которых разрешён организацией.

## Чистый репозиторий

Репозиторий создан из явного списка исходных файлов. В него не переносились временные ответы сайтов, загруженные скрипты OWA, диагностические файлы, пользовательская вспомогательная функция подключения или скриншоты.

Корпоративный домен заменён получением имени текущего сервера OWA. Тесты используют `example.com`. Адрес личного развертывания отсутствует. Существующая рабочая установка пользователя хранится отдельно от этого репозитория.

Перед первым публичным размещением:

```sh
npm ci
npm test
git status --short
git ls-files
```

Просмотрите именно список отслеживаемых файлов и историю. `.gitignore` не защищает секреты, вписанные непосредственно в разрешённый исходник или текст документации.

Публичный репозиторий: https://github.com/mainiken/owa-calendar-bridge. В публичную историю включены только проверенные исходники и документация. Начальный коммит использует нейтральную подпись `OWA Calendar Bridge contributors <contributors@example.invalid>`.

## Ограничение разрешений Tampermonkey

Исходный шаблон сопоставляется с HTTPS-адресами `https://*/owa/*`, а публичные страницы `https://*/owa/calendar/*` исключены. Страница `INSTALL.html` принимает адрес OWA и подготавливает скрипт с `@match` и `@exclude` только для этого сервера. Обработка адреса идёт локально. Адрес домена — публичная конфигурация, не пароль, но он может показывать, для какой организации сделан вариант инструмента.

Имя сервера передаётся только собственному обработчику Google и закрепляется за профилем при первом изменении календаря. Перенос одного профиля на другой сервер отклоняется, чтобы разные рабочие календари не перезаписывали один набор копий.
